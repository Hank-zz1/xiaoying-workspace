# PRD 生成器

## 概述

生成符合行业最佳实践的、结构清晰的产品需求文档（PRD），帮助产品经理创建清晰、可执行的需求文档，使各方利益相关者对齐并指导开发团队。

## 核心工作流

当用户请求创建 PRD 时（例如"为登录功能创建一个 PRD"），遵循以下流程：

### 第一步：收集上下文

在生成 PRD 之前，通过对话收集关键信息：

**必填信息：**
- **功能/产品名称**：我们在构建什么？
- **问题陈述**：解决什么问题？
- **目标用户**：为谁构建？
- **业务目标**：我们要达成什么？
- **成功指标**：如何衡量成功？
- **时间线/约束条件**：有无截止日期或限制？

**发现提问清单：**

1. 你想解决什么问题？
2. 这个功能的主要用户/受众是谁？
3. 关键的业务目标是什么？
4. 有什么技术约束需要注意？
5. 成功是什么样子的？如何衡量？
6. 这个功能的时间线是什么？
7. 什么明确不在范围内？

**注意**：如果用户已经提供了详细的需求简报或需求，可以跳过部分问题。始终针对缺失的关键信息进行澄清。

### 第二步：生成 PRD 结构

PRD 应包含以下章节：

1. **执行摘要** — 高层次概述（2-3 段）
2. **问题陈述** — 清晰的问题描述
3. **目标与目的** — 我们要达成什么
4. **用户画像** — 我们在为谁构建
5. **用户故事与需求** — 详细的功能需求
6. **成功指标** — KPI 和衡量标准
7. **范围** — 在范围内和范围外
8. **技术考量** — 架构、依赖、约束
9. **设计与 UX 要求** — UI/UX 考量
10. **时间线与里程碑** — 关键日期和阶段
11. **风险与缓解** — 潜在问题和解决方案
12. **依赖与假设** — 我们依赖的前提
13. **未决问题** — 尚未解决的条目

### 第三步：创建用户故事

为每个主要需求生成用户故事，使用标准格式：

```
作为 [用户类型]，
我想 [执行动作]，
以便 [获得价值/收益]。

验收标准：
- [具体的、可测试的标准 1]
- [具体的、可测试的标准 2]
- [具体的、可测试的标准 3]
```

### 第四步：定义成功指标

根据产品类型选择合适的指标框架：

- **AARRR（海盗指标）**：获客、激活、留存、收入、推荐
- **HEART 框架**：愉悦度、参与度、采纳度、留存率、任务完成率
- **北极星指标**：代表核心价值的单一关键指标
- **OKR**：目标与关键结果

### 第五步：验证与审查

检查 PRD 完整性：
- 所有章节是否存在
- 用户故事格式是否正确
- 是否定义了成功指标
- 范围是否清晰
- 是否还有占位文本未完成

## 使用场景

### 场景 1：新功能 PRD

用户请求："为我们的移动应用创建一个暗色模式的 PRD"

执行：
1. 询问关于暗色模式的发现性问题
2. 使用模板生成 PRD
3. 为用户故事创建：主题切换、偏好持久化、系统级同步、设计 token 更新
4. 定义成功指标（采用率、用户满意度）
5. 识别技术依赖（设计系统、平台 API）

### 场景 2：产品优化 PRD

用户请求："写一个改善搜索功能的需求文档"

执行：
1. 收集当前搜索功能的限制信息
2. 识别用户痛点和期望的改进
3. 生成 PRD，重点关注：当前状态分析、提议的增强、影响评估
4. 创建优先级排序的用户故事
5. 定义改进前后的对比指标

### 场景 3：新产品 PRD

用户请求："我需要一个新数据分析仪表盘产品的 PRD"

执行：
1. 全面的发现（市场分析、用户调研）
2. 生成完整 PRD：市场机会、竞品分析、产品愿景、MVP 范围、上市考虑
3. 详细的用户故事和验收标准
4. 多阶段里程碑定义
